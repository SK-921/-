# 第6章 データベース

この章では「関係データベースのしくみ」「正規化」「SQL」「トランザクション」を整理します。SQLは、実際に小さな表を書いて手で結果を作ってみると、問題文の読み違いが減ります。

---

## 1. 要点

### 関係データベースの基本
- データを表（関係）で管理する。行を**タプル（組）**、列を**属性**と呼ぶ
- **候補キー**：行を一意に識別できる、必要最小限の属性（の組）
- **主キー**：候補キーの中から選んだ1つ。値の重複は許されず、NULL も許されない
- **外部キー**：ほかの表の主キー（候補キー）を参照する属性。参照先に存在しない値は入れられない（参照制約）。外部キー自体は重複してよく、NULL も許される場合がある

### 正規化
同じデータを何か所にも持たないように表を分け、更新時異状（一部だけ書き換わって矛盾する、など）を防ぐ手順です。
- **第1正規形**：繰返し項目をなくし、すべての属性の値が単一の値（それ以上分けない値）になっている
- **第2正規形**：第1正規形であり、すべての非キー属性が、各候補キーに**完全関数従属**している（候補キーの一部だけで決まる「部分関数従属」がない）
- **第3正規形**：第2正規形であり、非キー属性が候補キーに**推移的関数従属**していない（非キー属性が、ほかの非キー属性によって決まらない）

### 関係演算
- **選択**：条件に合う**行**を取り出す
- **射影**：指定した**列**を取り出す
- **結合**：共通の属性の値をもとに、2つの表を1つにつなぐ

### SQL（問合せ）
```
SELECT 列, 集約関数(列)
FROM 表
WHERE 行の条件
GROUP BY 列
HAVING グループの条件
ORDER BY 列 [ASC | DESC]
```
- 処理の順番は FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY
- 集約関数：COUNT、SUM、AVG、MAX、MIN
- COUNT(*) はすべての行を数え、COUNT(列) はその列が NULL の行を数えない
- BETWEEN a AND b は a 以上 b 以下（両端を含む）
- LIKE の % は0文字以上の任意の文字列、_ は任意の1文字
- NULL かどうかは = ではなく IS NULL / IS NOT NULL で調べる
- DISTINCT は重複した行を1つにまとめる

### トランザクション
- 一連の処理を1つのまとまりとして扱う単位。確定は**コミット**、取り消しは**ロールバック**
- **ACID 特性**：原子性（全部実行されるか、全く実行されないか）、一貫性（データに矛盾がない状態を保つ）、独立性（同時に動くほかのトランザクションの影響を受けない）、耐久性（コミットした結果は障害が起きても失われない）
- **排他制御**：共有ロック（読取り用。共有ロック同士は同時にかけられる）、専有ロック（更新用。ほかのロックとは同時にかけられない）
- **デッドロック**：2つ以上のトランザクションが、互いに相手のロック解除を待って先へ進めなくなる状態
- **障害回復**
  - ロールバック：**更新前ログ**を使い、未完了の処理を取り消す
  - ロールフォワード：**更新後ログ**を使い、コミット済みの処理をやり直す
  - システム障害では、チェックポイント以降にコミット済みのものをロールフォワード、未コミットのものをロールバックする
  - 媒体障害では、バックアップを復元してから、更新後ログでロールフォワードする

---

## 2. 覚え方

### 正規化は「繰り返し → 一部 → 間接」
第1は**繰り返し**をなくす、第2はキーの**一部**だけで決まるものを分ける、第3はほかの属性を通して**間接的**に決まるものを分ける、と1語ずつ覚えます。

### 選択は「横に切る」、射影は「縦に切る」
表を横にスライスすると行（選択）、縦にスライスすると列（射影）。SQL では WHERE が選択、SELECT 句の列指定が射影にあたります。

### WHERE は「グループの前」、HAVING は「グループの後」
WHERE で行をふるいにかけてからグループにまとめ、HAVING でグループをふるいにかけます。

### ログは「前は戻す、後は進める」
更新**前**ログで元に**戻す**（ロールバック）、更新**後**ログで先へ**進める**（ロールフォワード）。

---

## 3. 間違えやすいポイント

- **集約関数は WHERE に書けない**：「合計が10以上のグループ」は HAVING SUM(…) >= 10 と書きます
- **SELECT 句と「選択」**：名前は似ていますが、SELECT 句で列を指定するのは関係演算の「射影」です
- **第2正規形が問題になるのは複合キーのとき**：候補キーがすべて1つの属性だけなら、部分関数従属は起こりません
- **外部キーは重複してよい**：重複不可・NULL 不可なのは主キーです
- **NULL と 0 は別物**：NULL は「値がない」ことで、= NULL と書いても条件は真になりません
- **共有ロックと専有ロック**：読むだけの処理同士は同時に進められますが、更新が絡むと待ちが発生します

## 4. 例題（自作）

**問題**　表「受講記録」（主キーは 学生ID と 講座 の組）に対して次のSQL文を実行したとき、得られる結果はどれか。

| 学生ID | 講座 | 時間 |
|---|---|---|
| S01 | Java | 3 |
| S02 | Java | 2 |
| S01 | DB | 4 |
| S03 | DB | 1 |
| S02 | Web | 6 |
| S03 | Java | 2 |
| S01 | Web | 1 |

```
SELECT 学生ID, SUM(時間) AS 合計
FROM 受講記録
WHERE 時間 >= 2
GROUP BY 学生ID
HAVING COUNT(*) >= 2
ORDER BY 学生ID
```

ア　S01 7、S02 8
イ　S01 8、S02 8、S03 3
ウ　S01 7、S02 8、S03 2
エ　S01 7

### 解説

処理の順番（WHERE → GROUP BY → HAVING）どおりに進めます。

**① WHERE 時間 >= 2**：時間が1の行（S03のDB、S01のWeb）を除き、5行が残ります。

**② GROUP BY 学生ID**

| 学生ID | 残った行の時間 | COUNT(*) | SUM(時間) |
|---|---|---|---|
| S01 | 3, 4 | 2 | 7 |
| S02 | 2, 6 | 2 | 8 |
| S03 | 2 | 1 | 2 |

**③ HAVING COUNT(*) >= 2**：S03 は1行しかないので除かれます。

結果は「S01 7、S02 8」で、正解は **ア** です。

**検算**：①で残った5行の時間の合計は 3 + 2 + 4 + 6 + 2 = 17。②の SUM の合計 7 + 8 + 2 = 17 と一致するので、グループ分けに漏れはありません。

**選択肢のわな**
- イ：WHERE を飛ばしたときの答え。S01 は 3 + 4 + 1 = 8、S03 は 1 + 2 = 3 で、全員が2行以上になります
- ウ：HAVING を飛ばしたときの答え。S03 の1行だけのグループが残ってしまいます
- エ：「>= 2」を「> 2」と読み違えたときの答え。時間が2の行も消えるため、S02 は6の1行だけになり HAVING で除かれます
